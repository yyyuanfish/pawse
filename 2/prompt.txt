Goal
Gemini Live is what the Google DeepMind prize judges, but Pawse doesn't use it yet: voice today is record-a-WAV, then generateContent. Build a real-time Live session where the owner talks to Pawse, Pawse answers out loud, and calls tools on the existing backend while it talks.

Tasks

POST /api/v1/live/tokens: the backend mints a single-use, short-lived ephemeral token locked to GEMINI_LIVE_MODEL (gemini-3.8-live), the system prompt and the tool declarations. The permanent key never reaches the browser. Requires explicit Gemini consent.

Tools run server-side at POST /api/v1/live/tool-calls (the browser forwards each call): assess_and_find_vets (care requests), search_policy (knowledge search), draft_vet_call_script (voice scripts), open_clinic_call (tel: link, behind an app confirm dialog; telephony stays not connected).

Frontend moved to Frontend: Gemini Live voice client (mic, playback, transcript, tool chips) #22 (Nami); contract in docs/GEMINI_LIVE.md.

Tests in tests/test_live.py (consent, missing key, locked setup, key never returned, safe 502, concurrency 429).

Docs: README, VALIDATION, ARCHITECTURE, API contract/OpenAPI, HACKATHON, .env.example, gemini skill. Update the repo description.

Manual check in Chrome with a real mic (after Frontend: Gemini Live voice client (mic, playback, transcript, tool chips) #22), results recorded in docs/VALIDATION.md.

## 1. Backend: `pawse/live.py` (313 lines)

- **Model default:** `os.getenv("GEMINI_LIVE_MODEL") or "gemini-3.8-live"` (`live.py:194`). `.env.example:36`, `voice.py:277` and `legacy.py:15` use the same default.
- **Consent:** `TokenRequest.share_with_gemini: Literal[True]` (`live.py:114`) and `ToolCall.share_with_gemini: Literal[True]` (`live.py:139`). Without consent you get 422.
- **Missing key:** 503 (`live.py:190-192`).
- **Token locking:** `setup()` (`live.py:104-109`) is sent as `bidiGenerateContentSetup` with `uses: 1` (`live.py:199-201`). It fixes the model, `responseModalities: ["AUDIO"]`, the system prompt, the tool declarations, and input/output transcription. The key travels only in the `x-goog-api-key` header. Any upstream failure returns a generic 502 (`live.py:206-207`), and a test checks the upstream text is not leaked.
- **Tools (`live.py:39-81`):** five, all `NON_BLOCKING`. The issue lists four. The extra one is `set_insurance_profile`, which is not in the issue or in the `GEMINI_LIVE.md` token-response example.
  - `assess_and_find_vets` runs `run_workflow`. It uses the owner's location only if they shared it, otherwise `ZURICH`.
  - `search_policy` returns demo-policy evidence only, never an approval. It first needs an insurance profile.
  - `draft_vet_call_script` reuses `draft_script`.
  - `open_clinic_call` returns `ui.action = "confirm_call"` with `call_url`. It only works for clinic IDs from this owner's last search.
- **Concurrency:** 3 tool calls per owner and 15 globally, else 429 (`live.py:286`). Tool failures return HTTP 200 with `response.error` so the conversation continues.

## 2. Which frontend uses Live
- **`pawse/static/*` (served at `/`) has no Live code.** It is the original page and the Mimi rehearsal.
- **The React app at `/app` uses it, but only behind a flag.**
  - `web/src/config.js:13-18`: `?live=1` sets all three agents to `live`. `?demo=1` forces mock. Otherwise the `VITE_VOICE_AGENT`, `VITE_CLINIC_SEARCH` and `VITE_PHONE_AGENT` env values apply, defaulting to **mock**.
  - `web/src/agents/index.js:24-26`: `createVoiceAgent` returns `createGeminiLiveAgent` when voice is live. `?voice=rest` selects the older `createLiveVoiceAgent` (record, WAV, POST `/api/v1/voice/transcriptions`). Without the live flag it returns `createMockVoiceAgent`.
  - `web/src/pages/VoiceCall.jsx:82` calls `createVoiceAgent({lang, shareWithGemini: consent, voice: gradiumVoice ? {engine:'gradium', voiceId} : null})`.
  - `docker-compose.yml:25-27` sets the three `VITE_*` variables to `live`. The Dockerfile sets none, so the Cloud Run build defaults to mock. The production `/app/` therefore only uses Live with `?live=1`. `Home.jsx:58` has a "Use backend agents" link to `?live=1`.
- **Call path:**
  1. `VoiceCall.jsx` calls `createVoiceAgent`.
  2. `geminiLiveAgent.start()` posts `/api/v1/live/tokens` (`geminiLiveAgent.js:106`).
  3. It calls `ai.live.connect` from `@google/genai` with the token and `apiVersion` v1alpha (`:107-108`).

## 3. STT/TTS and the Gradium question
- **Default Live (no voice choice):** Gemini does both. The agent sends mic audio (PCM 16 kHz) to Gemini, which answers with native AUDIO. Gemini's input and output transcription feed the captions.
- **Gradium mode** (`voice={engine:'gradium'}`, only for `en` and `de`; `VoiceCall.jsx:43`, `gradiumVoice.js:6-35`):
  - **Hearing:** mic frames go to Gradium streaming STT instead of Gemini (`geminiLiveAgent.js:104`). The finished turn is sent to Live as text, `send({text})` (`:113`).
  - **Speaking:** Gemini's own audio is dropped (`:88`). Live's output transcript is cut into sentences and streamed to Gradium TTS (`speakNew`, `:27-34`), played at 24 kHz.
  - **Fallback:** if Gradium STT fails, the agent drops back to Gemini's voice (`:115`).
  - **Auth:** Gradium access uses one-use tokens from `/api/v1/voice/stream-tokens`, so the key stays on the server.
- **Is Live set to AUDIO or TEXT?** AUDIO, in two places: the server-locked setup (`live.py:106`) and the client config (`geminiLiveAgent.js:108`). In Gradium mode Gemini still generates audio that is discarded. That wastes tokens and latency, and the text comes only from `outputTranscription`.
- **Could Live run in TEXT modality?**
  - The code already uses the text path for input: `send({text})` is used for Gradium STT turns, typed messages and the intro prompt.
  - A TEXT mode would need `setup()` to take a modality parameter, because the token locks the modality. The client would then read `modelTurn.parts[].text` instead of `outputTranscription`.
  - I did not confirm that `gemini-3.8-live` supports TEXT output. Native-audio Live models often accept only AUDIO, so this is untested. Check the `gemini-live-api-dev` skill or run a test mint first.
  - Nothing in the repo sets TEXT today.
