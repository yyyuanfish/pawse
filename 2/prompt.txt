Root cause. test_simulated_rehearsal_is_labelled_on_screen started failing after #56 removed the "Demo mode · scripted" badge. Underneath: the Dockerfile builds web/ with no VITE_* settings, so config.js fell back to 'mock' and the public /app/ ran the scripted voice, clinic and phone agents (verified in the deployed bundle). With the badge gone, owners saw a scripted conversation with no simulated label (rule 3). #63 then rewrote the test to only look for a "Simulated rehearsal" link in settings, which passed without the problem being fixed.

Fix

web/src/config.js: default 'live'; scripted only via ?demo=1 or explicit VITE_*=mock (docker-compose already set live).
web/src/App.jsx: role="note" banner "Simulated rehearsal · scripted, no real calls or bookings" above every screen while any agent is scripted or the phone rehearsal runs. The production /app/ stays badge-free, as Clinic search endpoint + connected-insurance card #56 intended.

e2e: label in viewport on /app/?demo=1 home and still visible on the call screen; absent on /app/.
